Карта

Сквозная схема

На схеме четыре запуска. Узел laim-detector в режиме train собирает бандл. Тот же узел в режиме inference получает бандл через model_in и помечает трассы. Узел LAIM RCA проверяет каждый флаг с помощью LLM, а узел LAIM anomaly report собирает из результата HTML-отчёт. Выровненные по вертикали блоки детектора выполняют один и тот же код: при обучении он подбирает параметры, при инференсе применяет их.

s1 · ars/stages/s1__data.py · ars/data

Подготовка данных: от спанов к последовательностям

Метка аномалии — чистый хеш trace_id, поэтому план сплита известен ещё до расчёта признаков. Благодаря этому отбор признаков и нормализация видят только train-normal трассы, хотя сама инъекция идёт позже, в пространстве признаков и эмбеддингов. Числовая дорожка (EPI) и текстовая (SEM) сходятся в одну строку на пару (trace_id, agent_id).

Контракт данных (ars/specification/spec.py, ТЗ v1.9.2) — 46 полей в 11 группах: id 6, время 2, статус 2, классификация 2, текст 2, LLM 11, HTTP 5, Kafka 4, LangGraph 7, сервис 3, meta 2. NULL запрещён: «не применимо» кодируется сентинелами (-1, -1.0, false, '', root, outside, NONE, STATUS_CODE_UNSET). Обязательны 13 полей: все id, оба времени, aef_kind, input_text, output_text и два session-флага. Одно невалидное обязательное поле отбрасывает всю трассу. Гейт стоит в laim/pipeline.py перед s1 и проверяет только обучающие спаны: strict пишет train_spans_validated.parquet, warn только логирует.

Классы инъекции (ars/data/anomalies_injection.py). Профиль ячеек (aef_kind, agent_id) строится по всему корпусу до инъекции.

s2 · ars/stages/s2__detector.py · ars/models/m2__detector

Детектор: два LSTM-автоэнкодера и FMLP над их латентами

Ветви обучаются по очереди: EPI-AE, SEM-AE, затем FMLP-AE на замороженных нормализованных латентах. Флаг ставит только ошибка FMLP-AE (e_comb) против порога. Ошибки ветвей в флаге не участвуют, но входят в калибровку p_anomaly, поэтому у флагнутой трассы может быть p < 0,5.

Сетка экспериментов (ars/configuration/experiments/e2__detector.py, CODES): активны два кода, laim по умолчанию запускает оба, победитель — максимум youden на val-mixed.

s3 · ars/stages/s3__classifier.py · ars/models/m3__classifier

Классификатор типа аномалии

Supervised-стек на чистом JAX. Он учится на инъецированных аномалиях из VAL ∪ TEST, а в инференсе размечает только флагнутые трассы внутри build_product_contract. Класса «норма» нет: ложное срабатывание детектора тоже получит один из пяти типов. Отсевом ложных срабатываний занимается RCA-узел.

s4 · m2__detector/attribution.py · ars/stages/s4__rca.py

Атрибуция: где именно ошибся автоэнкодер

Поэлементная ошибка ветви считается в её же функции потерь. Среднее по признакам даёт ошибку спана, среднее по валидным шагам — ошибку признака. Для каждой трассы это даёт индексный JSON rca_attribution. Для флагнутых export_detector_rca добавляет имена, каталог спанов и значения в натуральных единицах — блок laim.detector_rca/1.

Блок detector_rca — структура, а не пример значений (s4__rca.py:189–205)

// только для строк с detector_is_anomaly; строгий JSON без NaN
{ "schema": "laim.detector_rca/1", "agent_id",
  "scores": { p_anomaly, reconstruction_error // = e_comb
            , threshold
            , branch_z:   { behavior, semantic }  // robust z
            , flag_share: { behavior, semantic }  // comb_share_epi
            , logit:      { behavior, semantic, combined, bias } },
  "sequence": { spans, scored, truncated },
  "spans": { // только упомянутые, без сентинелов
    "<span_id>": { name, kind, status, status_message,
      parent_span_id, llm_model, llm_total_tokens,
      http_method, http_path, http_status_code,
      kafka_topic, graph_node, service, start_time,
      duration_s, input_excerpt, output_excerpt } }, // ≤ 200 симв.
  "feature_info": { "<feature>": { base, aggregation,
                   window, log1p, scope // step | sequence } },
  "behavior": {
    spans:    [ { rank, index, span_id, error, error_share,
                  vs_typical, drivers: [ { feature, direction,
                  observed, expected, observed_raw,
                  expected_raw, clipped, error } ] } ],
    features: [ { rank, feature, direction, observed, expected,
                  observed_raw, expected_raw, clipped, error,
                  error_share, vs_typical,
                  peak_span_index, peak_span_id } ] },
  "semantic": { spans: [ { rank, index, span_id, error,
                          error_share, vs_typical } ] } }

Как считаются значения. observed и expected = z · scale + shift, то есть шкала самого признака (для лог-признаков — после log1p). *_raw обращает log1p только там, где это осмысленно (max, min, mean, квантили); для std и sum сырых значений нет. clipped ставится, если |z| упёрся в клип ±20. vs_typical — ошибка, делённая на медиану ошибки нормальных обучающих трасс.

Имена, которые легко перепутать. Колонки detector_z_epi и detector_z_sem в detections.parquet — это нормализованные латентные векторы (128 и 768), вход s3. Robust z-оценки ошибок живут только внутри rca_attribution и detector_rca (branch_z).

rca/ · отдельный узел SberDS · main.py::main

RCA-узел: LLM проверяет флаг и пишет причину

Узел не импортирует ars и laim, с детектором его связывает только JSON test_anomalies. Улики из detector_rca и связи между трейсами строятся детерминированно, без LLM. Отчёт о разработке агента, если подан, становится главным контекстом промпта. LLM возвращает вердикт и короткое RCA без категорий, а записи с вердиктом normal отбрасываются как ложные срабатывания.

Запись на входе (test_anomalies) — 11 полей в фиксированном порядке и detector_rca

{ "anomalies": [ {
  _comment, trace_id, starttime, endtime,
  anomaly_type,          // из s3, пусто при сбое
  confidence,            // round(p_anomaly · 100)
  business_description,
  user_query,            // первый input_request
  agent_response,        // последний output_request
  tech_details,          // RCA-узел больше не заполняет
  rca_results,           // "" — заполнит RCA-узел
  detector_rca           // только если флаг
} ] }

Запись на выходе (res): та же запись без detector_rca, поля детектора не меняются, rca_results теперь объект

rca_results: {

anomaly_report/ · отдельный узел SberDS · main.py::main

Отчёт по аномалиям: последний узел цепочки

Узел берёт res RCA-узла (или сразу test_anomalies детектора) и рендерит самодостаточный HTML без JS и JSON-сводку со светофором. Зависимостей нет, только стандартная библиотека Python.

ШагЧто происходит
Фильтр 7остаются записи с confidence ≥ min_confidence (по умолчанию 75). Детектор пишет туда round(p_anomaly · 100), RCA-узел это поле не трогает, поэтому в отчёт попадают трассы с p ≥ 0,75. Записи тестов дрифта и КМ исключаются, остальные сортируются по confidence
Типыanomaly_types = auto: блоки о типах показываются, только если s3 заполнил anomaly_type хотя бы у одной записи; show и hide включают и выключают их принудительно
HTML«Описание показателей» (типы и шкала confidence), «Сводка», «Перечень аномалий»: карточки с trace_id, временем, типом, confidence, запросом, ответом и RCA. trace_id в тексте RCA ссылаются на карточки, категории и служебные метки вычищаются
Светофорamber, если показана хотя бы одна аномалия, иначе green: порога «сколько аномалий — плохо» пока нет

Выходные порты: anomaly_report — HTML в панели «Отчёт по аномалиям», all_results — сводка

Что всплыло при разборе

Ниже расхождения, найденные при сверке схемы с кодом. Номера совпадают с метками на схемах. Пункт 1 перепроверен запуском на polars 1.43.2 и по tests/golden/golden.json, остальные — чтением указанных строк.

Статус (27.09.2026): пункты 1–6 исправлены на ветке claude/audit-05-fixes (F-75, F-76, F-77, F-78, F-84, F-81). Коммиты и тесты перечислены в разделе «Статус исправлений» файла AUDIT_05_findings.md. Пункт 7 (F-80) открыт: сначала нужно решение по продукту. Схемы выше по-прежнему показывают состояние на 10f9e28.

  1. 1

    Отбор признаков вырождается в алфавитный порядок высокий

    В s1__data.py:227 корреляция stats_df.select(cols).corr() считается до заполнения пропусков. У любого столбца с null она равна NaN (например, у всех *_rolling_std_w*), а в polars NaN.abs() > 0.999 истинно. Такие пары считаются дублями, и правило разрыва ничьей удаляет имя, которое позже по алфавиту. В golden-файле ровно 45 признаков EPI, и все начинаются на «a» (action_entropy, actions_per_agent, avg_word_length_sem_*). Это объясняет «схлопывание» из PLAN.md, и согласованный следующий эксперимент (max_correlation=0.9 и др.) его не лечит. Исправление: заполнять пропуски до corr() или считать NaN-корреляцию нулём. Поменяются golden-пины.

  2. 2

    Инференс кодирует эмбеддинги на CPU средний

    cmd_infer (laim/pipeline.py:354–361) собирает S1Config без device, и срабатывает значение по умолчанию 'cpu' (c1__data.py:38). В prepare (pipeline.py:210) устройство передаётся. JAX-детектор на инференсе идёт на GPU, а USER-bge-m3 — на CPU, поэтому скоринг больших корпусов упирается в процессор.

  3. 3

    detector.threshold_metric ни на что не влияет средний

    build_grid назначает каждому эксперименту метрику по позиции в CODES (youden, precision, …), а threshold_metric_or предпочитает её конфигу (e2__detector.py:63, 188–190; s2__detector.py:440). Deep-эксперимент порогуется по precision, а выбор между экспериментами идёт по youden, что структурно его штрафует.

  4. 4

    Эксперименты вне CODES молча отбрасываются средний

    s2__detector.py:577–578 фильтрует EXPERIMENTS по имени, а hub_mse_hub_16_4 из согласованного эксперимента в PLAN.md закомментирован в CODES. Из трёх запрошенных кодов запустятся два. Ошибка будет, только если не совпадёт ни один.

  5. 5

    Документация устарела в двух местах низкий

    CLAUDE.md пишет, что платформа вызывает ars/main.py::main. На деле descriptor.json:125–128 указывает на run.py::main → laim.platform.run_node. README перечисляет rca_report_str среди колонок detections.parquet, но cmd_infer его не создаёт: analyze_anomalies зовётся только из legacy-пути, а rca_results заполняет RCA-узел.

  6. 6

    Seed инъекции не связан с runtime.seed низкий

    s1 создаёт InjectionConfig с планом по умолчанию, где Plan.seed = 12345 (s1__data.py:1132, 1162; anomalies_injection.py:200). Смена seed перетасует сплит, но набор аномальных трасс останется прежним. Отдельно известно (OQ-8): data.scale_floor и data.norm_z_clip не доходят до s1.

  7. 7

    Отчёт не показывает флаги с p < 0,75 на заметку

    Узел отчёта оставляет записи с confidence ≥ min_confidence = 75 (anomaly_report/main.py:259–263), а confidence = round(p_anomaly · 100), и RCA-узел его не меняет. Флаг же детектор ставит по e_comb > порога, отдельно от p. Поэтому аномалия, подтверждённая LLM, но с p = 0,6, есть в res, а в отчёт не попадёт. Если так не задумано, порог стоит согласовать с калибровкой или фильтровать по вердикту RCA.
