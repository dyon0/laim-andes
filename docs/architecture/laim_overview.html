Обзор архитектуры LAIM

Как AEF-трейс проходит через систему. Узел laim-detector обучает детектор и оценивает новые трейсы, узел LAIM RCA проверяет каждое срабатывание с помощью LLM, узел LAIM anomaly report формирует HTML-отчёт. Это сокращённая версия: слои моделей, форматы данных и параметры узлов показаны в подробной схеме.

  • 46полей спана, 13 обязательных
  • 1024измерения эмбеддинга USER-bge-m3
  • 128 + 768латентные векторы двух LSTM-автоэнкодеров
  • 5классов синтетических аномалий
  • 3узла SberDS и внешний LLM

Компоненты

Что делает каждая часть

Данные s1 · ars/stages/s1__data.py

  • Контракт: 46 полей спана, 13 обязательных; трейс с невалидным обязательным полем отбрасывается целиком (гейт off | warn | strict).
  • EPI: около 2 900 кандидатов из 39 признаков спана и 11 признаков трейса; отбор по заполненности, доле моды и корреляции на нормальных трейсах TRAIN.
  • SEM: эмбеддинг output_text моделью deepvk/USER-bge-m3, 1024 измерения; на GPU — по реплике модели на каждую карту.
  • Синтетические аномалии: dpi, ipi, mp, hallucination, bias, по умолчанию 20 % трейсов; класс выбирается хешем trace_id и назначается, только если в трейсе есть спаны-мишени.
  • Разбиение по trace_id: норма 70/15/15, аномалии 0/70/30; EPI нормализуется медианой и IQR по TRAIN.
подробнее: s1 →

Детектор s2–s4 · ars/stages, ars/models

  • EPI-AE и SEM-AE (LSTM) сжимают последовательность спанов в латентные векторы 128 и 768.
  • FMLP-AE восстанавливает их конкатенацию (896); ошибка e_comb выше порога даёт is_anomaly = 1.
  • p_anomaly — отдельная логистическая калибровка трёх ошибок; порог, веса калибровки и выбор эксперимента подбираются на VAL.
  • s3 (стекинг) присваивает помеченным трейсам один из пяти типов аномалий.
  • s4 раскладывает ошибку по спанам и признакам и формирует блок detector_rca.
подробнее: s2 →

Узел RCA rca/ · отдельный узел

  • Вход — test_anomalies: 11 полей записи и detector_rca. Узел не импортирует ars и laim.
  • Без LLM строятся сигнал детектора (ветвь, сила, подозрительные спаны) и связи между трейсами по общим кодам и терминам.
  • Отчёт о разработке агента, если подан, становится главным контекстом промпта.
  • LLM возвращает вердикт: anomaly и uncertain остаются, normal исключается как ложное срабатывание; RCA — текст до 600 символов без категорий.
  • Режимы llm, llm_fallback, detector_only; все решения пишутся в rca_audit.
подробнее: узел RCA →

Отчёт и эксплуатация anomaly_report/ · run.py · laim/

  • Отчёт показывает записи с confidence ≥ 75, то есть с p_anomaly ≥ 0,75; типы — только если работал s3; светофор amber при наличии аномалий.
  • Пакет модели передаётся по порту model_out → model_in: zip в base64 внутри JSON с sha256.
  • Инференс проверяет отпечаток модели эмбеддингов и кодирует тексты на устройстве узла (GPU при device = gpu).
  • Локально: run.py {synth|validate|prepare|train|eval|infer|all}; результаты — в runs/<id>/.
  • Конфигурация проверяется до запуска: неизвестный ключ, некорректный код эксперимента или план внедрения вызывают ошибку.
